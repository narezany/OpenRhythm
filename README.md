# Open Rhythm

A cursor-based rhythm game. White cubes fly at a 3×3 grid; your cursor has to
be on the cube when it lands. Where inside the cell you caught it decides the
rank — timing barely matters, aim does.

Built with Godot 4 and GDScript. Inspired by Rhythia / Sound Space, and it
imports their maps.

> **Open Rhythm is a game, not a music player.** The tracks are here so there
> is something to play to. If a song is good, go listen to it where the artist
> actually gets paid. See [Music and rights](#music-and-rights).

## Features

* **Square mode** — 3×3 grid, zone-based judging, PERFECT → BULLSHIT ranks.
* **Hold notes** — long cubes you have to stay on. Nothing else is charted
  while one runs; there is only one cursor.
* **Click notes** — cubes that have to be pressed, not just covered. Off by
  default: a chart can carry them, the CLICKS modifier turns them on.
* **Modifiers** — TARGET, BLACKOUT, CAGE, SPEED UP, SLOW DOWN, MIRROR, HIDDEN,
  CLICKS and CLICKY, each with its own score multiplier.
* **Three stories** and six original OST tracks with Easy / Normal / Hyper
  charts generated by `tools/gen_media.py` and `tools/gen_pack2.py`.
* **Map editor** — a piano roll with a waveform, beat grid, snapping, undo,
  copy/paste, multi-select and hold-length dragging, plus an onset-based
  auto-generator.
* **Imports `.sspm`** (Rhythia / Sound Space Plus, v1 and v2) and the legacy
  Sound Space map string.
* **Any audio** — `.wav`, `.ogg`, `.mp3`. Song folders or `.zip` packs.
* **Map scripting** — a song can bring a timeline that changes the background
  colour, throws its own pictures up behind the playfield, reskins the cubes,
  makes them huge, and shakes the camera. Events are data, not code, so a map
  pack from a stranger stays safe to open.
* **Offset calibration** — tap along with a metronome and the game works out
  your audio delay for you.
* **Versus** — two players, one chart, higher score wins. A direct
  peer-to-peer connection with no server: one side hosts, the other types their
  address. Both must be on the same build and holding the same chart, checked
  by hashing the notes, so custom maps work as long as they are identical.
* **Replays**, local records, lifetime stats and achievements.
* **Accessibility** — reduce motion, reduce flashes, cursor size, video off.
* **Six languages** — English, Russian, Chinese, German, Dutch and Spanish,
  generated from one table by `tools/gen_loc.py`.
* **Gamepad and keyboard** cursor control with rebindable keys.
* Runs on Linux, Windows, Android and the web.

## Playing

Grab a build from [Releases](../../releases), or run it from source:

```bash
godot --path . 
```

Add your own songs by dropping a folder or a `.zip` into the library folder
shown on the **Songs** screen, then pressing **RESCAN**.

## Building

Godot **4.7** with the matching export templates installed.

```bash
godot --headless --path . --export-release "Linux" build/OpenRhythm.x86_64
godot --headless --path . --export-release "Windows Desktop" build/windows/OpenRhythm.exe
godot --headless --path . --export-release "Web" build/web/index.html
godot --headless --path . --export-release "Android" build/OpenRhythm.apk
```

The web export needs cross-origin isolation headers (`COOP`/`COEP`) on the
host; itch.io has a checkbox for it. Theora video is excluded from the web
build, so songs with a clip play without one.

### Android signing

Release credentials are **never** stored in `export_presets.cfg`. Pass them
through the environment instead:

```bash
export GODOT_ANDROID_KEYSTORE_RELEASE_PATH=/path/to/release.keystore
export GODOT_ANDROID_KEYSTORE_RELEASE_USER=your-alias
export GODOT_ANDROID_KEYSTORE_RELEASE_PASSWORD=...
```

If you ever type them into the editor's export dialog, Godot writes them back
into `export_presets.cfg` — clear the fields before committing. CI fails the
build if a password ends up in that file.

## Making maps

See **[docs/MAP_FORMAT.md](docs/MAP_FORMAT.md)** for the song folder layout,
`map.json`, note fields and hold notes.

In the editor: the 3×3 playfield on the left places notes at the playhead, the
timeline at the bottom is where you actually shape the chart.

| | |
|---|---|
| Space | play / pause |
| ← → | seek by the snap step (Shift: a bar) |
| 1…8 | snap 1/1 … 1/16 |
| Ctrl+Z / Ctrl+Y | undo / redo |
| Ctrl+C / Ctrl+V | copy / paste at the playhead |
| Ctrl+D | duplicate the selection forward |
| Ctrl+A | select all |
| Delete | delete the selection |
| H | toggle a one-beat hold on the selection |
| C | toggle click notes on the selection (or on new notes) |
| Ctrl+S | save |
| T | test the chart |
| drag | rubber-band select |
| Ctrl+click | add a note |
| drag right edge | set a hold length |
| wheel / Ctrl+wheel / middle drag | scroll / zoom / pan |

Saving a built-in song forks it into your library first — `res://` is inside
the binary and cannot be written to.

The waveform is drawn for `.wav` audio, or from a `waveform.json` if the song
ships one. Ogg and MP3 cannot be decoded from
GDScript, so those charts get the beat grid only.

## Music and rights

The bundled OST — `neon_drift`, `hyper_drive` and the tutorial track — is
generated by `tools/gen_media.py` and ships under the project licence.

Any other song folder contains music by someone else. Those folders are
**not** part of this repository (see `.gitignore`) and must not be
redistributed without the author's permission. The game shows a notice on
first launch pointing players at the original releases.

If you are an artist and want a track out of the game, say so in
[Telegram](https://t.me/openrhythmforum) or
[Discord](https://discord.gg/rc79e2sfqC) and it goes.
